# ir-lang v2.0.0-alpha.1 — the SSA IR of the native path

**A pre-release of the 2.0 redesign.** ir-lang 1.0 was a self-contained function
IR with four types and no calls, memory, or exceptions. 2.0 is the IR the family's
native compiler path runs through — after monomorphization, closure conversion,
pattern compilation, and effect lowering, and before the optimizer and instruction
selection — designed once against the needs of every later phase. The normative
specification is `_lexersketch/specs/IR.md`.

It is published as an alpha because no consumer exercises it yet (D18): the HIR
lowering, opt-lang, and instruction selection come next, and 2.0.0 follows once they
have used it end to end. Consumers of 1.x (codegen-lang, jit-lang, aot-lang,
linker-lang) stay on 1.x until the coordinated Wave M.

## What is ir-lang?

An SSA intermediate representation: a `Module` of functions, globals, and aggregate
types; function bodies are control-flow graphs whose blocks take parameters instead
of phi nodes. It owns the IR, the builder and rewrite API, the validator, the
textual form, and a reference interpreter. It has no dependencies.

## What's new in 2.0.0-alpha.1

### A module, and the declarations a real program needs

Functions carry interned signatures with calling-convention tags (`fast`, `c`,
`sysv64`, `win64`, `aapcs64`), linkage (`local`, `export`, `import`), and attributes
(`nounwind`, `noreturn`, and `nogc` are checked; the rest are hints). Globals have
initializers and relocations (addresses of functions and globals). Aggregates —
structs, packed structs, arrays — have C layout and are reached through
`field_addr` and `elem_addr`.

### Types that carry signedness

`i8`..`i64`, `u8`..`u64`, `f32`, `f64`, `bool`, `ptr`, `ref`. Every
signedness-dependent operation of the shared operation semantics takes its
signedness from its operand type, so an instruction cannot disagree with its domain,
and HIR's typed operands map one to one. The trade-off against sign-less integers is
argued in IR.md §2.1.

### Every operation carries its policy

All of `specs/OPS.md` — integer, float, comparison, and conversion operations — with
the overflow, division-by-zero, shift, and float-to-int policy on each instance,
exactly the fields each operation needs (the validator rejects a missing or extra
field). `wrap`, `mask`, and `saturate` never fail; `trap` aborts; `error` routes to an
explicit edge. `promote` does not exist: every IR value is statically typed. This
settles ISSUES M44 and the root of H10: division by zero and `MIN / -1` mean the same
thing on every tier.

### Errors and exceptions are edges

```text
check div<overflow=wrap,div_zero=error> v5, v0 to b5(res0) error b1(err)
invoke @parse(v1) to b2(res0) unwind b3(exn)
resume v9
```

`check` runs a fallible operation and passes the OPS error code to its error edge;
`invoke` passes a callee's exception payload to a landing pad, which only unwind edges
may reach; `resume` unwinds out of the function. Tail calls (`tail_call`,
`tail_call_indirect`) require matching returns and convention.

### Safepoints that relocate GC references

Every call that is not `nogc`, every `invoke`, and every `safepoint` instruction is a
safepoint. References needed after it are listed in its GC list and the safepoint
defines their relocated values. The validator enforces that no reference — and no
pointer derived from one — is live across a safepoint, and that derived pointers never
escape. So the stack map of every safepoint is exactly its GC list, and a moving
collector is supported from day one (ARCHITECTURE §8).

### A builder that is also the rewrite API

The `Builder` lowers into a body and rewrites it: insertion at any position,
`replace_all_uses` in O(1), `remove_inst`, `replace_inst`, `split_block`,
block-parameter edits, `remove_block`, and `compact`, which is the only operation that
renumbers and returns the mapping. Every instruction is checked as it is added, with
the validator's own code. `set_terminator` refuses to overwrite a terminator (M42).

### A validator that is the contract

Entry parameters against the signature and single definition (M43), typing and exact
policies, exception-edge and attribute rules, dominance (the Cooper–Harvey–Kennedy
algorithm and one linear walk of the dominator tree), and the safepoint rules. It is
total: corrupted state, mutated text, and hostile rewrites are rejected, never a panic.

### A textual form that round-trips

`Display` prints a deterministic text; `parse` reads it back to the same module with
the same handles. The parser is iterative and budgeted (input size; entity ids capped
relative to the input).

### A reference interpreter (feature `interp`)

Implements OPS exactly, reports undefined behaviour instead of executing it, and
simulates a moving collector with a GC epoch per safepoint, so a missing relocation
fails at run time. Its per-operation `eval_*` functions are what opt-lang's constant
folding will call. It is the oracle opt-lang and backend-lang test against.

## How it is tested

- OPS conformance: every integer type × policy × the OPS edge values, against
  independent reference arithmetic; IEEE special cases; `ieee_rem` against exact
  rational arithmetic.
- Differential: random programs with loops, calls, invokes, tail calls, stack and
  global memory, checked arithmetic, exceptions, and traps run in an independent
  evaluator and, lowered, in the interpreter — before and after a print/parse round
  trip.
- Properties: builder output validates; print/parse round-trips; rewrite sequences
  keep the IR valid and its behaviour; the validator and parser never panic on mutated
  input; compaction round-trips.
- Benchmarks at 100k and 1M instructions (build, validate, print, parse, compact,
  safepoint validation) scale linearly.

## Breaking changes and migration

Everything. `CHANGELOG.md` → 2.0.0-alpha.1 has the full list and a table mapping each
1.0 call to its 2.0 form.

## Not in this release

- No crate lowers HIR into ir-lang 2.0 yet, and no backend reads it.
- Automatic statepoint insertion (filling GC lists from liveness) is planned for
  2.0.0, together with an SSA updater; see `dev/ROADMAP.md`.
- Vector types are reserved.
