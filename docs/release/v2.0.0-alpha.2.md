# ir-lang v2.0.0-alpha.2: OPS v2, SSA construction, statepoint insertion

**A pre-release of the 2.0 redesign.** alpha.1 shipped the IR, builder, validator,
textual form and interpreter. alpha.2 closes the gaps its first consumers reported:
opt-lang 0.2.0, backend-lang 0.3.0, and the HIR lowering (irgen-lang, ISSUES P29).
The normative specs are `_lexersketch/specs/IR.md` (updated) and `specs/OPS.md` v2.

It is still an alpha (D18). 2.0.0 follows once the HIR lowering, the optimizer and
instruction selection have used it end to end.

## What's new in 2.0.0-alpha.2

### OPS v2

- `BinaryOp::Pow` on integers: exact repeated squaring, `0 ** 0 = 1`, overflow per
  policy (`wrap` keeps the low bits). A negative exponent raises `NegativeExponent`
  (OPS code 6, E0006), or traps with that code under `trap`.
- `BinaryOp::Pow` on floats uses `ls_pow`, the family's shared float power routine
  (`specs/ops-vectors/pow.md`). It is bit-identical across every tier and lives in
  `core`, so `no_std` optimizers can fold it. `f32` widens, computes and rounds once.
- `Shift::Saturate`: an amount at or above the width gives `0`, or `-1` for `shr` of
  a negative signed value. A negative amount is still `ShiftOutOfRange`.
- `BinaryOp::can_error(Policy, Type)`, `UnaryOp::can_error(Policy)` and
  `ConvOp::can_error(Policy)` expose the exact rule the validator uses to decide
  whether an operation must sit in a `check` terminator.

### SSA construction for mutable locals

This uses the Braun et al. (2013) algorithm, with block parameters in place of phi
nodes. The API is `Variable` plus `Builder::{declare_var, def_var, use_var,
seal_block, seal_all_blocks, is_sealed}`.

- A lowering passes only a block's own arguments on its edges; the builder appends
  the variables' arguments.
- Trivial parameters are forwarded when their block is sealed.
- `seal_all_blocks` removes the remaining trivial parameters, repeating until
  nothing changes.
- A variable read before any assignment gives zero of its type.
- The construction is iterative throughout, with definitions held in an
  open-addressing table.
- It also works when adding code to an existing body through `Module::edit`.

### Automatic statepoint insertion

`Builder::insert_statepoints()` computes reference liveness exactly as the validator
defines it. It then:

1. fills in the missing GC-list entries at every safepoint;
2. passes relocated references through both edges of an `invoke`;
3. repairs SSA where relocated versions meet;
4. removes trivial parameters;
5. validates the result.

On any error the function is restored exactly. The pass is budgeted because its
output can be quadratic in its input: `insert_statepoints_within(budget)` sets the
budget, and the default is `DEFAULT_STATEPOINT_BUDGET` = 2^26.

### Rewrite helpers the optimizer asked for

- `Builder::remove_block_params(&[Value])` removes any number of block parameters,
  with their edge arguments, in one linear pass.
- `Builder::move_inst(Inst, Position)` moves an instruction in O(1) and keeps its
  handle and results.

## How it is tested

- `ops_v2`: `pow` and saturating shifts across every integer type and policy,
  checked against independent reference arithmetic.
- `pow_vectors`: all 122 vectors from the shared float `pow` spec, compared bit for
  bit.
- `ssa`: random programs with mutable variables are lowered through the builder,
  with blocks sealed both eagerly and lazily. Their results must match an
  independent evaluator and a memory-based lowering of the same program. The suite
  also checks:
  - that no trivial block parameter survives;
  - that deep program shapes run without recursion;
  - that misuse is refused;
  - edits to existing bodies.
- `statepoint`: insertion on random programs with calls, invokes and loops. The
  interpreter's moving-collector simulation catches any missing relocation. Budget
  failures and error rollback leave the function unchanged.
- Benchmarks cover SSA construction, statepoint insertion, and `ls_pow`.
- Gate: fmt; clippy on stable, 1.99 and MSRV 1.85; tests and docs on Windows and
  Linux (WSL2).

## Breaking changes and migration

- **Signed integers are fallible in more places.** On a signed integer type, `pow`
  (under `wrap` or `error`) and `shl`/`shr` (under `shift = saturate`) can raise an
  error. They are valid only inside a `check`. Code that used
  `Policy::can_error()` to choose between a `check` and a plain instruction must
  call `op.can_error(policy, ty)` instead.
- **OPS code 6 is taken.** `OpError::from_code(6)` is now `NegativeExponent`.
- **New enum variants:** `BinaryOp::Pow`, `Shift::Saturate`,
  `OpError::NegativeExponent`, and five `BuildError` variants. All of these enums
  are `#[non_exhaustive]`.
- **Builder state changes:**
  - `Builder::compact` drops the state used for variable construction.
  - `split_block` returns `VariablesActive` while any block is still unsealed.

`CHANGELOG.md` → 2.0.0-alpha.2 has a full migration table.

## Not in this release

- No crate lowers HIR into ir-lang 2.0 yet. irgen-lang 0.2 is the next consumer.
- There is no SSA updater for definitions that already exist. Variable construction
  is a tool for lowering new code, not for updating existing SSA.
- Vector types are still reserved.
