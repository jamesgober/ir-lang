# ir-lang v2.0.0-alpha.4: resource bounds

**A pre-release of the 2.0 redesign.** alpha.4 fixes three places where hostile input could
make the crate use far more memory or time than its limits suggest. Nothing else changes.

It is still an alpha. 2.0.0 follows once the HIR lowering, the optimizer and instruction
selection have used it end to end.

## The parser's tables are budgeted across the module

Function bodies store values and blocks densely by id, so a body that names `v1000` holds a
table of 1001 entries. Ids were capped at `64 * input length + 4096`, but per id, not per
module. Many short functions that each named one high id added up to a table per function, so
memory grew with the square of the input: 11.7 KB of text could allocate about 2.8 GB.

The same cap now also bounds the total length of the value and block tables of all bodies
together. Past it, the parser stops with the new `ParseErrorKind::TooManyEntities { limit }`,
positioned at the id that would have grown a table past the budget. Printed modules are far
inside it, and sparse ids still parse.

## Dominators in near-linear time

`Module::validate` computed dominators with the iterative Cooper-Harvey-Kennedy algorithm. It
is fast on ordinary code, but quadratic on some graphs: a long chain of blocks that all branch
to one join block made it climb the chain once per predecessor. It is now Lengauer-Tarjan with
path compression, `O(e log n)`, with an explicit stack so no graph recurses. The results are
the same; a randomized test checks the new algorithm against the old one.

## Register files count against the interpreter's memory limit

`Limits::memory` bounded the simulated address space, but each frame also holds a register
file of 8 bytes per value of its function, reachable or not. Deep recursion through a function
with many values allocated that memory outside the limit: with default limits, a run could
reach 152 MiB of host memory under a 4 MiB limit.

The register files of all live frames are now held to `Limits::memory` bytes as well. A call
that would pass it is `InterpError::OutOfMemory`, and the charge is released when the frame
returns. The pool of reused register files stays within the same bound.

This is a behaviour change: a program that recursed deeply through a large function and used
to end in `StackOverflow`, or finish, may now end in `OutOfMemory`. Raise `Limits::memory` to
allow it.

## Upgrading

```toml
[dependencies]
ir-lang = "2.0.0-alpha.4"
```

MSRV stays 1.85.
